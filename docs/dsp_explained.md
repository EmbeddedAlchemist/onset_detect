# 零基础信号处理解说

> 这份文档假设你没有信号处理背景。每一节回答三个问题：
> **这一步在做什么？为什么必须做？不做会怎样？**
> 代码里的注释与本文结构一一对应，可以对照着看。

---

## 0. 先把声音变成数字

### 0.1 采样率 16000 Hz

麦克风输出的是连续电压，ADC 每秒量 16000 次，存成一串整数。
"每秒 16000 个点"意味着**能表示的最高频率是 8000 Hz**（这叫 Nyquist 频率，永远是采样率的一半）。

所以：
- 这个项目里 **4 kHz 以上只有 4–8 kHz 这一段**，8–16 kHz 的镲片泛音不存在；
- 1024 点分析里，最高只能看到第 512 个频点。

### 0.2 16 bit

每个采样点是 `-32768 … 32767` 之间的整数。我们把 32768 当作"满刻度 1.0"（这叫 Q15，见第 10 节）。
一个数字的"量化台阶"是 1/32768 ≈ -90 dB，也就是这套数字音频本身的最低噪声底。

### 0.3 为什么要环形缓冲

实时处理时，音频中断每来 64~256 个点就喊一次"有新数据了"。
但我们分析一帧需要 1024 个点，所以必须**把最近收到的点存起来**。

```
环形缓冲（实际长度 1280 = 窗长 1024 + 跳步 256）

   ... [已分析的旧样本] [ 当前这一帧 1024 点 ] [正在被写入的 256 点] ...
                          ↑                    ↑
                       任务在这里读        中断在这里写
```

**为什么要多留 256 点**：如果环长度正好等于 1024，中断写新数据时会**覆盖掉当前帧最旧的 256 个点**，
任务读到一半数据就变了（数据撕裂）。多留一个跳步的间隙，读写永不重叠 → 不需要加锁，也不需要额外拷贝。

**代价**：多占 256×2 = 512 字节 RAM。**收益**：零拷贝、零锁、零额外延迟。

## 1. 为什么要"分帧"

声音的频率成分**随时间变化**。整首歌做一次 FFT 只会得到一个平均值，没有意义。
所以要把信号切成一小段一小段，每段做一次 FFT，看"这一小段里有哪些频率"。

本项目取：**窗长 1024 点（64 ms），跳步 256 点（16 ms）**。

```
样本:  |------ 1024 ------|
              |------ 1024 ------|      ← 相邻帧重叠 768 点（75%）
                     |------ 1024 ------|
       ↑0ms        ↑16ms       ↑32ms
```

### 为什么是 64 ms

频率分辨率 ≈ 1 / 窗长。64 ms → 能分开相隔约 **15.6 Hz** 的两个频率。

- 底鼓的基频 ~50 Hz，贝斯基频 ~50–200 Hz，两者**在频率上是重叠的**，
  必须分得足够细才能看出"底鼓是在 50 Hz 还是 80 Hz"；
- 贝斯的相邻谐波（80 / 160 / 240 Hz）需要至少 80 Hz 的分辨率才能分开，64 ms 足够。

### 为什么跳步是 16 ms

跳步决定**时间分辨率**：跳步 16 ms，起振时刻的判定误差就在 ±8 ms 左右。
跳步越小越准，但每秒要做的 FFT 次数越多（跳步 256 → 62.5 次/秒；跳步 64 → 250 次/秒，算力 ×4）。

### 这里有个绕不过去的矛盾（时频不确定性）

> 窗越长 → 频率分得越清，但时间越模糊；
> 窗越短 → 时间越准，但频率糊成一团。

底鼓的"下滑音"（60 ms 内从 120 Hz 滑到 50 Hz）需要**看得清频率**；
起振时刻需要**看得准时间**。两者不可兼得，64 ms / 16 ms 是折中结果。
这就是为什么算法后续要同时看"包络（时间）"和"谱（频率）"两类证据。

## 2. 加窗（Hann）—— 消除"截断"带来的假频率

### 做什么

把每一帧的 1024 个点，乘上一条两端为 0、中间为 1 的钟形曲线：

```
Hann:  0 → 平滑上升到 1 → 平滑下降回 0
        ___
      /     \
    _/         \_
```

### 为什么

直接截取 1024 点，相当于给信号乘了一个"方波闸门"。方波在频域有很长的尾巴，
会让**一个纯音的能量糊到相邻频点上**（这叫"频谱泄漏"）。泄漏会让相邻子带互相污染，
底鼓的能量"漏"进贝斯带，判据就废了。

加 Hann 窗后，帧两端平滑过渡到 0，泄漏被大幅压低。

### 代价（很重要）

Hann 窗把帧**中央**的权重加大、**两端**的权重压小。所以：
- 一个在第 500 点发生的鼓点，要到第 500 点之后的帧才会被"重点看到"；
- **flux 的峰值会比真实起振时刻晚约 16–24 ms**（这是常数偏差，P1 会标定后减掉）。

> 代码位置：`fft_fixed.hann_q15()`，在 `detector._frame_flux()` 里逐点相乘。

## 3. FFT —— 把"1024 个时间点"变成"513 个频率强度"

### 做什么

傅里叶变换回答一个问题：**这一帧里，每个频率各有多少能量？**

```
输入：1024 个时间样本（±32767 的整数）
输出：513 个复数 X[k]，k = 0 … 512
      第 k 个对应的频率 = k × 15.625 Hz
      k=0 → 0 Hz（直流）    k=4 → 62.5 Hz    k=51 → 797 Hz
```

### 为什么用"实数 FFT"

输入是实数（不是复数），数学上有一半的频点是重复的（共轭对称）。
实数 FFT 只算前一半，**省一半算力**：把 1024 点拆成 512 点复数 FFT，再用公式拼回来。

### 为什么要"幅值平方"而不是"幅值"

我们要的是每个频点的强度 `|X| = sqrt(re² + im²)`。
但 **sqrt 在 MCU 上很贵**，而我们后面要取对数——于是可以直接用 `|X|²`：

```
log(|X|) = 0.5 × log(|X|²)
```

一次乘加代替一次平方根，数学上完全等价。这就是代码里到处是 `sq`（squared）的原因。

> 代码位置：`fft_fixed.rfft_q15()` 返回的就是 `|X|²`（int64）。

## 4. 取对数（dB）—— 这一步是"抗音量干扰"的关键

### 做什么

把 `|X|²` 变成以 2 为底的对数，用 Q8.8 定点存（1.0 倍频程 = 256，1 个 LSB ≈ 0.023 dB）。

### 为什么必须做（这是全篇最重要的一节）

假设贝斯在 100 Hz 的能量是 10000，底鼓来了，在这个频点又加了 1000：

| 域 | 贝斯单独 | 加上底鼓 | 变化 |
|---|---|---|---|
| 线性 | 10000 | 11000 | **+10%** |
| dB | 40 dB | 40.4 dB | **+0.4 dB** |

线性域里 10% 的变化，会被更响的成分掩盖；**取对数后，"加了多少 dB"与原有能量大小无关**。
这就是"dB 域做差 = 对增益不变"：无论这段音乐是安静还是炸裂，底鼓带来的 dB 增量是同一量级。

> 顺带一提：人耳感知响度本身也是对数关系，所以 dB 也是"听起来的变化"。

### 怎么用整数算 log2（没有 FPU 的 MCU 上）

任何整数 x 都能写成 `x = 2^e × (1 + t)`，其中 t ∈ [0,1)：

1. **整数部分 e**：数一下二进制有多少位（Cortex-M3 / RV32 都有 `CLZ` 指令，一条指令搞定）；
2. **小数部分 log2(1+t)**：把 t 切成 16 段，用一张 17 项的查找表 + 线性插值。

总误差实测 **0.0044 倍频程 = 0.038 dB**，对 3–6 dB 的检测阈值完全够用。

> 代码位置：`fxp.log2_q8_8()`。

## 5. 分成 10 个子带 —— 为什么不能把 0–300 Hz 当一个整体

### 问题

如果直接把 0–300 Hz 所有频点的能量加起来：

```
贝斯谐波占了大部分 bin 的能量        → 总和 ≈ 贝斯能量
底鼓的 thump 只占其中几个 bin       → 它的贡献被"稀释"了
```

结果就是：**底鼓叠在贝斯上时，总和的涨幅很小，检不出来**（这正是你遇到的问题之一）。

### 做法

按频率切成 10 个带，各自独立算变化量，再分别判定：

| 带 | 频率 | 里面通常是什么 |
|---|---|---|
| sub | 16–62 Hz | 底鼓 thump、超低音 |
| kick | 63–109 Hz | 底鼓 body |
| bass | 110–203 Hz | 贝斯基频 |
| lowmid | 203–406 Hz | 贝斯 2/3 次谐波、军鼓 body |
| mid | 406–797 Hz | 乐器主体 |
| uppermid | 0.8–1.5 kHz | 人声/乐器泛音 |
| presence | 1.5–2.5 kHz | 军鼓噪声、click |
| treble | 2.5–4 kHz | click 主体 |
| high | 4–5.5 kHz | hi-hat |
| air | 5.5–8 kHz | hi-hat / cymbal |

这样"贝斯只占 bass 带、底鼓主要占 sub/kick 带、click 占 treble 带"就分开了，
后面才有办法做判别（判据 A/B/C/D）。

### 带内为什么要取相邻 ±1 bin 的最大值

频率抖动、窗函数的相位、扫频，都会让一个峰在相邻 bin 之间来回跳。
取 ±1 bin 最大值，可以让"同一个声音"的带能量更稳定，不会因为跳 bin 产生假的涨落。

> 代码位置：`bands.py` 的 `BAND_EDGES_HZ` / `band_bin_edges()`。

## 6. 谱通量（spectral flux）—— 起振检测的核心

### 做什么

```
flux[t][band] = max(0, 本帧该带能量 - 上一帧该带能量)      （单位：dB）
```

**只保留正值**：起振的本质是"能量突然上升"。能量下降（衰减）不是起振，
所以负的部分直接归零。

### 为什么"相邻两帧相减"就够

因为一个鼓点必然让某些频点的能量在几十毫秒内显著上升。
看这条上升的斜率，就是最便宜、最通用的起振证据。

### 它的固有缺陷（也就是你要解决的问题）

flux 只知道"能量涨了"，不知道**为什么会涨**：

| 现象 | flux 的反应 | 真实含义 |
|---|---|---|
| 底鼓 | 强正脉冲 | 真鼓点 ✅ |
| 贝斯音符起始 | 强正脉冲 | 不是鼓 ❌ |
| 侧链拐点（贝斯被压下去又回来） | 正脉冲 | 不是鼓 ❌ |
| 贝斯 + 底鼓同时 | 只有中等正脉冲 | 真鼓点但容易漏 ❌ |

三种错误一一对应你要解决的三个问题。flux 本身无法区分，必须靠**额外的判据**（P3/P4）。

> 代码位置：`detector._frame_flux()`。

## 7. 自适应阈值 —— 为什么不能写死一个数

音乐有安静的主歌、炸裂的副歌。固定阈值要么副歌全是误报，要么主歌全是漏检。

### 分位数是什么

把最近几秒内某个带的 flux 值从小到大排好：
- **中位数（50% 分位）**：比它大的值占一半；
- **80% 分位**：比它大的值占 20%。

阈值取"分位数 + 一个固定增量（4.1 dB）"，就能跟着段落自动升降。

### 为什么用直方图而不是排序

排序 85 个数需要插入排序（几十条指令 + 内存搬移），MCU 上太贵。
直方图把数值按 1.5 dB 一档丢进 16 个桶里，求分位只需要**从头累加 16 次**。
更新一个桶就是"加 1"，O(1)。

计数太多时整体右移一位（忘记旧数据），保证它能跟上音乐的变化。

### 当前版本的问题（已知，P2 修）

大多数帧的 flux 是 0（没有起振），所以中位数恒为 0 → 阈值退化成一条 4.1 dB 的平线
→ 任何谱变化都会触发（实测 23 次/秒，明显过检）。
P2 会改用 **高分位（80/90）+ 相对峰值**的组合。

> 代码位置：`quantile.py`，在 `detector._on_frame()` 里调用。

## 8. 从"一条曲线"到"一个鼓点"—— 峰值挑选

flux 是一片起伏的曲线，一个鼓点会形成一个"小山包"。要把它变成一个时间点：

### 8.1 局部极大（只取山顶）

```
flux:  0 → 2 → 7 → 15 → 8 → 2 → 0
                     ↑ 只在这里出事件
```

判定"我是山顶"需要看到左右邻居，所以**必须晚 1 帧才能确认**（16 ms）。
这 16 ms 叫**延迟（delay）**，不是**前瞻（lookahead）**——
因为我们用的是已经到达的数据，只是在等下一帧数据来确认上一帧。

### 8.2 迟滞（hysteresis）

触发后要等 flux 落回阈值的 3/5 以下，才允许下一次触发。
否则一个山包上的小抖动会连续触发好几次。

### 8.3 最小间隔（min IOI）

物理下限：人手/鼓机不可能在 45 ms 内打两次同一个鼓。
所以硬性禁止同一带 45 ms 内二次触发。

> ⚠️ 注意：这个值**不能设成 120 ms**。128 BPM 的 16 分音符间隔是 117 ms，
> 太长的不应期会吃掉真鼓，比误报更糟（它会破坏节拍相位）。

> 代码位置：`detector._eval_center()`。

## 9. 时间戳、延迟、以及"不前瞻"

```
真实起振 t0
   │
   │  ← 帧还要"长大"到能覆盖这个事件（Hann 窗中央权重最大）
   ▼
帧中心              ← 检测事件绑定的时间戳（含常数滞后，P1 标定后减掉）
   │
   │  ← 再等 1 帧来确认"是不是山顶"
   ▼
事件输出            ← t0 + 约 16~32 ms
```

整个过程中：
- **从不使用未来的采样点**；
- 只是"看到的数据暂时不立刻拍板"，这属于延迟，允许；
- PCM 缓冲大小固定 1280 点，**不随延迟增长**。

## 10. 定点数（Q15）—— 为什么不能直接写 float

### 问题

Cortex-M3 和 RV32IM **没有硬件浮点单元（FPU）**。一个 `float` 乘法要靠软件模拟，
大约 50–100 条指令，而整数乘法只要 1–2 条。整条链每秒要做几百万次乘加，
用 float 直接慢两个数量级。

### Q15 是什么

把"1.0"约定成 32768：

| 真实值 | Q15 存储 |
|---|---|
| 1.0 | 32768（超出 int16，所以 1.0 用 32767 近似） |
| 0.5 | 16384 |
| -0.5 | -16384 |
| 0.0000305 | 1 |

两个 Q15 相乘，结果是 Q30，所以要**右移 15 位**变回 Q15：

```
mul_q15(a, b) = (a * b) >> 15
```

三个必知的坑：

1. **溢出**：Q15×Q15 的中间结果必须用 32 位装（`a*b` 最大约 1.07e9）。
2. **截断偏向负无穷**：`(-3) >> 1 = -2` 而不是 -1.5。小信号经过许多级右移后会有轻微向下偏置
   （实测极低电平时最多 0.2 dB，远小于检测阈值，不影响结果）。
3. **1.0 表示不出来**：32767/32768 = 0.99997，误差 0.003%，对音频无所谓。

### block floating point（FFT 里的动态缩放）

FFT 内部每级运算会让数值**增长最多 1.414 倍**（旋转因子是复数）。
如果一路不缩放，1024 点会增长约 1000 倍 → int32 溢出。

两种解决办法：

| 方案 | 做法 | 缺点 |
|---|---|---|
| CMSIS 的做法 | **每级固定右移 1 位** | 1024 点总共损失 10 bit 有效位 → 16 bit 音频只剩 6 bit，小信号全被量化噪声淹没 |
| **本项目** | 每级先看最大值，超限才右移，并**记录一共移了多少位** | 需要一次 max 扫描（512 次比较，很便宜） |

关键点：右移把数值缩小了 `2^shift` 倍，所以最后在对数域要**加回** `(shift-1)` 个倍频程。
这一步如果符号写反，不同帧的数值就不可比，会凭空出现随音量跳变的假峰
（这个 bug 在 P0 的测试里真的出现过，现已被 `test_rfft_bias_stable_across_levels` 永久锁死）。

> 代码位置：`fft_fixed.rfft_q15()`（移位与记录）、`rfft_log_offset()`（补偿）。

## 11. 把"听感"翻译成"图上的形状"

这一节是后面所有判别特征的来源。假设你听一段音乐，能听出底鼓和贝斯，
那么"你听到的是什么"可以翻译成下面这些可计算量：

| 你听到的 | 物理事实 | 图上长什么样 | 可计算的特征 |
|---|---|---|---|
| 底鼓"咚" | 60 ms 内从 ~120 Hz **下滑**到 ~50 Hz，且很快衰减 | sub 带能量相对 kick 带先升后落 | **A1** 子带重心比 |
| 贝斯音符 | 有明确音高，稳定持续几百毫秒 | 谐波位置固定不动，bass/lowmid 带持续有能量 | **B** 衰减斜率、**D** 部分集 |
| 底鼓的"嗒" | 鼓槌/踏板产生的宽带冲击（2–6 kHz） | treble/presence 带有一个极短脉冲 | **C** 高频同步 |
| 侧链恢复 | 贝斯被压下去，几十毫秒后又回到**原来的电平和谐波结构** | 能量回升，但**没有新的谐波**、**没有高频 click** | **D** 部分集一致性 |

**这四条就是 P3/P4 要实现的判别特征**，对应的正是你提出的三个难题：
贝斯误判（A1/B/D）、侧链恢复（D + 软门控）、掩蔽漏检（A1 + C 不受绝对幅度影响）。

## 12. 术语小抄

| 术语 | 含义 |
|---|---|
| 帧 / hop | 一次分析的时间窗 / 相邻两帧的间隔 |
| bin | FFT 输出的一个频率槽，本项目 1 bin = 15.625 Hz |
| 谱通量 flux | 相邻帧能量差（只取正） |
| 起振 onset | 声音能量突然上升的时刻 |
| 包络 envelope | 信号幅度随时间的慢变化曲线 |
| 侧链 sidechain | 鼓一响就把贝斯压下去的混音处理 |
| 部分集 partials | 一个有音高的声音在谱上呈现的一组峰（基频 + 谐波） |
| dB / 倍频程 | 对数刻度；1 倍频程 = 频率翻倍 = 6.02 dB |
| Q15 / Q8.8 | 定点格式；Q15 是 1.0=32768，Q8.8 是 1.0=256（用于对数域） |
| 前瞻 lookahead | 使用尚未到达的采样点（本项目禁止） |
| 延迟 delay | 已有数据暂不处理，等后续数据到达再确认（允许） |
